1. 功能级RBAC数据模型
新增固定权限码：
ANSWER_USE
SEARCH_USE
DOCUMENT_VIEW
DOCUMENT_UPLOAD
DOCUMENT_MANAGE
KNOWLEDGE_BASE_MANAGE
RETRIEVAL_LAB_USE
ASSISTANT_MANAGE
IDENTITY_MANAGE
AUDIT_VIEW
STATS_VIEW
HARNESS_USE
数据库新增：
permissions
- code，字符串主键
- name
- description
- category
- sort_order

role_permissions
- role_id
- permission_code
- 联合唯一约束
要求：
- 一个角色可以绑定多个权限。
- 一个用户可以拥有多个角色。
- 用户最终权限为所有启用角色权限的并集。
- 停用角色后，其功能权限立即失效。
- is_super_admin=true 自动拥有全部权限。
- 不删除现有 user_roles 和文档ACL。
- 新增线性Alembic迁移，例如 0018_function_rbac.py。
- 必须提供完整 downgrade()。
- 不清空现有用户、角色、资料和权限数据。
2. 默认角色
迁移或初始化程序幂等创建以下角色：
默认角色	权限
普通员工	ANSWER_USE、SEARCH_USE、DOCUMENT_VIEW
资料维护员	普通员工权限，加 DOCUMENT_UPLOAD、DOCUMENT_MANAGE
知识库管理员	资料维护员权限，加 KNOWLEDGE_BASE_MANAGE
系统管理员	除 Harness 外的全部后台管理权限


要求：
- 重复执行不会创建重复角色或权限。
- 不自动修改现有普通用户的角色。
- 现有超级管理员不受影响。
- HARNESS_USE 暂时只允许超级管理员使用，不能因为普通角色勾选就绕过原来的管理员限制。
3. 后端权限解析器
在权限服务中增加：
has_permission(user, permission_code) -> bool
require_permission(user, permission_code) -> User
effective_permissions(user) -> set[str]
规则：
- 未登录返回 401 AUTH_REQUIRED。
- 已登录但无权限返回 403 PERMISSION_DENIED。
- 停用用户没有权限。
- 停用角色不参与权限合并。
- 超级管理员自动通过。
- 不能仅在前端隐藏按钮，后端必须逐接口验证。
- 权限拒绝写入审计日志，但审计失败不能覆盖原始403响应。
4. 当前用户接口
修改：
GET /api/auth/me
返回当前用户的有效权限码：
{
  "authenticated": true,
  "user": {
    "id": "...",
    "roles": ["普通员工"],
    "permissions": [
      "ANSWER_USE",
      "SEARCH_USE",
      "DOCUMENT_VIEW"
    ]
  }
}
要求：
- 只返回启用角色产生的权限。
- 超级管理员可以返回所有权限。
- 前端刷新后根据该字段恢复菜单。
- 前端不能自己根据角色名称推算权限。

7. 前端菜单与按钮控制
前端增加统一权限方法：
hasPermission(code: PermissionCode): boolean
hasAnyPermission(codes: PermissionCode[]): boolean
导航控制：
- 没有 ANSWER_USE：隐藏知识问答。
- 没有 SEARCH_USE：隐藏资料检索。
- 没有 DOCUMENT_VIEW：隐藏资料库。
- 没有 RETRIEVAL_LAB_USE：隐藏检索实验室。
- 拥有任意后台权限时才显示系统管理。
- 系统管理内部只显示用户有权访问的子菜单。
资料库控制：
- 没有 DOCUMENT_UPLOAD：隐藏单文件上传、批量导入。
- 没有 DOCUMENT_MANAGE：隐藏编辑、停用、删除、恢复和ACL操作。
- 没有 KNOWLEDGE_BASE_MANAGE：隐藏管理知识库入口。
要求：
- 页面刷新恢复原页面前重新校验权限。
- 用户权限被管理员修改后，下次接口请求必须立即由后端阻止。
- 收到 403 PERMISSION_DENIED 时显示“当前账号没有此功能权限”。
- 不能把前端隐藏当作安全控制。
8. 审计
新增或完善以下审计事件：
role_permissions_changed
authorization_denied
document_upload_denied
knowledge_base_manage_denied
审计内容至少包含：
- 当前用户ID。
- 接口路径。
- 请求方法。
- 缺少的权限码。
- 操作目标。
- 请求ID。
- 成功或失败状态。
严禁记录：
- 密码。
- Cookie。
- DeepSeek API Key。
- 完整敏感文档正文。
