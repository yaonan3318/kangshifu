P2-1：检索准确性增强
1. Query Rewrite 问题改写
用户输入：
日报中气泡后来怎么样了？

系统改写为：
查询日报中气泡检测项目近期进展，包括数据标注、模型训练、白光和红光检测、视频二分类及当前结果。

要求：
- 保留原问题
- 记录改写后的检索问题
- 支持关闭
- 改写失败时使用原问题
- 不允许改写改变用户原意
- 在检索实验室展示改写过程
2. 多轮对话上下文补全
例如：
用户：气泡检测项目进展怎么样？
用户：后来在 Windows 上成功了吗？
第二个问题需要补全为：
气泡检测项目后来是否在 Windows 环境完成模型训练？

要求：
- 只读取当前会话最近若干轮
- 不把整个历史会话全部塞入模型
- 新建会话后不继承旧话题
- 用户明显切换话题时停止继承
- 展示“系统实际用于检索的问题”
3. Multi-query 多查询召回
针对一个问题生成多个检索表达：
气泡检测进度
气泡模型训练结果
Windows YOLO 环境搭建
白光红光气泡识别
视频二分类进展
然后：
- 分别执行混合检索
- 合并结果
- 按 chunk_id 去重
- 使用 RRF 融合
- 最终交给 Reranker
建议默认生成2～4个查询，避免响应时间过长。
4. Reranker 精排正式启用
当前项目已经有可选 Reranker 基础，应完善：
- 管理页面配置开关
- 设置候选数量和最终数量
- 记录重排前后名次
- 检索实验室展示分数变化
- 模型不可用时自动退化为 RRF
- 评测启用前后的准确率和耗时
5. 元数据与结构化过滤
检索条件增加：
- 知识库
- 文件类型
- 文档标签
- 部门
- 上传人
- 创建时间
- 文档有效期
- 文档状态
- 文件夹路径
- 文档版本
必须先进行权限过滤，再把结果交给模型。
6. 中文检索优化
增加：
- 同义词词典
- 公司内部缩写词典
- 专有名词词典
- 中英文混合检索
- 拼写纠正
- 简称与全称映射
例如：
K8s → Kubernetes
日报 → 日报汇总、工作记录、周报
气泡 → 气泡检测、气泡识别、bubble
词典由管理员维护，不能写死在代码里。
