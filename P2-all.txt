P2-1：检索准确性增强
1. Query Rewrite 问题改写
用户输入：
日报中气泡后来怎么样了？

系统改写为：
查询日报中气泡检测项目近期进展，包括数据标注、模型训练、白光和红光检测、视频二分类及当前结果。

要求：
- 保留原问题
- 记录改写后的检索问题
- 支持关闭
- 改写失败时使用原问题
- 不允许改写改变用户原意
- 在检索实验室展示改写过程
2. 多轮对话上下文补全
例如：
用户：气泡检测项目进展怎么样？
用户：后来在 Windows 上成功了吗？
第二个问题需要补全为：
气泡检测项目后来是否在 Windows 环境完成模型训练？

要求：
- 只读取当前会话最近若干轮
- 不把整个历史会话全部塞入模型
- 新建会话后不继承旧话题
- 用户明显切换话题时停止继承
- 展示“系统实际用于检索的问题”
3. Multi-query 多查询召回
针对一个问题生成多个检索表达：
气泡检测进度
气泡模型训练结果
Windows YOLO 环境搭建
白光红光气泡识别
视频二分类进展
然后：
- 分别执行混合检索
- 合并结果
- 按 chunk_id 去重
- 使用 RRF 融合
- 最终交给 Reranker
建议默认生成2～4个查询，避免响应时间过长。
4. Reranker 精排正式启用
当前项目已经有可选 Reranker 基础，应完善：
- 管理页面配置开关
- 设置候选数量和最终数量
- 记录重排前后名次
- 检索实验室展示分数变化
- 模型不可用时自动退化为 RRF
- 评测启用前后的准确率和耗时
5. 元数据与结构化过滤
检索条件增加：
- 知识库
- 文件类型
- 文档标签
- 部门
- 上传人
- 创建时间
- 文档有效期
- 文档状态
- 文件夹路径
- 文档版本
必须先进行权限过滤，再把结果交给模型。
6. 中文检索优化
增加：
- 同义词词典
- 公司内部缩写词典
- 专有名词词典
- 中英文混合检索
- 拼写纠正
- 简称与全称映射
例如：
K8s → Kubernetes
日报 → 日报汇总、工作记录、周报
气泡 → 气泡检测、气泡识别、bubble
词典由管理员维护，不能写死在代码里。
P2-2：回答可靠性增强
1. 答案置信度
综合计算：
- 召回分数
- Reranker 分数
- 有效片段数量
- 多片段内容一致性
- 答案引用覆盖程度
页面展示：
- 高可信
- 中等可信
- 资料不足
不要展示难以理解的裸分数。
2. 无答案和低置信度处理
资料不足时禁止模型猜测，返回：
当前可访问的公司资料中没有找到足够依据。

并提供：
- 推荐相关资料
- 推荐换一种问法
- 是否使用 DeepSeek 通用知识
- 提交“缺失知识”反馈
需要区分：
- 公司没有相关资料
- 有资料但用户无权访问
- 检索到了低相关资料
- 本地模型不可用
不得向用户泄露其无权访问文档的名称。
3. 引用真实性校验
生成完成后检查：
- 答案中的每个事实是否能被引用片段支持
- 引用编号是否存在
- 引用文档是否仍可访问
- 引用是否对应正确页码、片段或幻灯片
- 删除或停用文档后旧答案引用的状态
没有依据的内容应删除或标记为“推断”。
4. 可追溯答案
点击引用后展示：
- 文档名称
- 页码、幻灯片或工作表
- 命中的原文
- 命中关键词
- 当前使用的文档版本
- 打开文档详情
- 下载原文件（有权限时）
5. 答案结构模板
不同问题使用不同模板：
- 制度问题：结论、适用范围、办理步骤、注意事项
- 技术问题：结论、实施步骤、代码或命令、风险
- 项目进度：时间线、当前状态、阻塞问题、下一步
- 对比问题：对比表格、差异、建议
- 汇总问题：主题归类、关键结论、引用来源
P2-3：助手角色增强
1. 助手角色真正参与回答
每个助手配置：
- 名称和头像
- 角色说明
- 系统提示词
- 可访问知识库
- 默认回答模板
- 召回数量
- 温度
- 本地模型
- 是否允许 DeepSeek
- 是否允许 Harness
- 是否允许联网
- 无答案策略
2. 建议预置助手
- 康师傅综合助手
- 人事制度助手
- 技术研发助手
- 产品资料助手
- 运维助手
- 项目进度助手
3. 用户端隐藏技术选项
普通用户页面不展示：
- DeepSeek 开关
- Harness 开关
- Kubernetes Context
- Namespace
- 模型温度
- 召回数量
这些由管理员在助手配置中决定。
页面只展示用户能理解的信息：
- 当前助手
- 使用哪些知识库
- 是否允许查询通用知识
- 是否允许执行运维任务
4. 助手欢迎页
每个助手显示：
- 能做什么
- 不能做什么
- 推荐问题
- 可访问资料范围
- 最近热门问题
P2-4：轻量 Chatflow
不建议立即开发 Dify 式自由拖拽画布，先实现可配置的流程节点和固定画布。
第一版节点
- 开始节点
- 问题分类节点
- 问题改写节点
- 知识库检索节点
- Reranker 节点
- 条件判断节点
- 本地模型节点
- DeepSeek 节点
- Harness 节点
- 答案校验节点
- 最终回答节点
基础能力
- 节点输入、输出变量
- 节点启用和停用
- 条件分支
- 节点失败处理
- 超时处理
- 调试运行
- 展示每个节点耗时
- 保存草稿
- 发布版本
- 回滚历史版本
- 不同助手绑定不同 Chatflow
推荐默认流程
开始
 → 问题分类
 → 上下文补全
 → Multi-query
 → 权限过滤
 → 混合检索
 → Reranker
 → 置信度判断
    ├─ 资料充分 → 本地千问 → 引用校验 → 回答
    ├─ 资料不足且允许DeepSeek → DeepSeek → 标记通用知识 → 回答
    ├─ 运维任务 → Harness → 人工确认
    └─ 无法回答 → 缺失知识提示
P2-5：用户体验与比赛展示
1. 回答过程可视化
回答过程中展示简洁状态：
正在理解问题
正在检索 3 个知识库
找到 12 个候选片段
正在筛选最相关资料
正在组织答案
正在核对引用
普通用户只看简要过程；管理员可以展开完整调试信息。
2. 流式输出优化
- 尽早返回首字
- 检索和模型请求支持取消
- 切换页面后继续生成
- 刷新页面后恢复生成状态
- 网络恢复后重新连接
- 防止重复提交
- 明确区分检索耗时和生成耗时
3. 推荐追问
回答底部生成2～4个追问，例如：
- 当前气泡检测项目还有哪些阻塞？
- Windows 环境最终训练出了哪个模型？
- 白光和红光模型有什么区别？
点击即可继续提问。
4. 答案操作
- 复制
- 重新生成
- 导出 Markdown/PDF
- 有帮助/没帮助
- 原因选择
- 补充反馈
- 举报敏感或错误答案
5. 知识缺口中心
自动记录：
- 未找到答案的问题
- 低置信度问题
- 用户评价“没帮助”的问题
- 高频但没有资料的问题
- 经常召回错误文档的问题
管理员可以：
- 指派负责人
- 补充资料
- 关联正确文档
- 重新运行问题
- 对比修复前后的答案
6. 首页数据展示
适合比赛演示：
- 知识库数量
- 文档数量
- 可检索片段数量
- 今日问答数量
- 平均响应时间
- 引用覆盖率
- 用户满意度
- 热门问题
- 知识缺口数量
P2-6：文档理解能力
1. 高质量 PDF 解析
- 标题层级识别
- 页眉页脚去除
- 多栏排版
- 表格提取
- 图片与图注关联
- 扫描 PDF OCR
- 页码映射
- 重复段落清理
2. Office 解析增强
- DOCX 标题和表格
- PPTX 页面标题、文本框、备注
- XLSX 按工作表和表格区域切片
- 合并单元格处理
- 图片 OCR
- 超长表格分块
3. 切片策略配置
按知识库配置：
- 固定长度切片
- 标题层级切片
- 段落切片
- 页面切片
- 表格切片
- 父子切片
- 重叠长度
- 最小、最大字符数
支持在页面预览切片效果后再建立索引。
4. 文档标签和知识图谱基础数据
先增加：
- 标签
  -作者
- 部门
- 主题
- 生效时间
- 失效时间
- 关联文档
- 替代版本
暂时不做完整 GraphRAG，但为后续实体关系检索保留数据。
P2-7：反馈驱动优化
当前已经有用户反馈基础，继续完善：
- 达到样本门槛后小幅影响排序
- 单个用户不能反复刷分
- 按知识库分别统计
- 记录反馈对应的检索配置版本
- 负反馈进入管理员处理队列
- 修改文档后重新验证历史负反馈
- 排序权重设置上限
- 反馈不能绕过关键词和语义相关性
不能直接因为点赞多就把无关文档排到前面。
P2-8：通用 Workflow，后置
等 Chatflow 稳定后再做，主要面向非聊天任务：
- 手动触发
- 定时触发
- Webhook 触发
- 文件上传触发
- 批量文档处理
- HTTP API 调用
- 条件分支
- 人工审批
- 重试
- 幂等控制
- 失败告警
- 执行历史
- Workflow 版本管理
示例：
上传工资文件
 → 检查文件格式
 → 提取员工信息
 → 敏感信息检测
 → 人工审批
 → 加入工资知识库
 → 通知管理员
