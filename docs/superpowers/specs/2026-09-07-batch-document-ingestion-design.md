# 本地资料库批量导入与批次管理设计

日期：2026-09-07

## 1. 背景与目标

当前系统已具备单文件上传、解析、OCR、切片、向量索引、混合检索和 RAG 问答能力。下一阶段首先验证本地批量导入可行性，使用户能够一次处理约 200 份资料，并在浏览器关闭、网络中断、单文件失败或程序重启后继续完成导入。

本阶段不实现登录和权限系统，不改变现有检索与问答主流程。原有单文件上传入口继续保留，已有文档必须无损兼容。

## 2. 范围

本阶段实现：

- 多文件选择、文件夹选择和 ZIP 导入；
- 每次批量上传创建导入批次；
- 保留文件夹相对路径；
- 文件级并发上传、进度和状态展示；
- 用户手动继续中断的批次；
- 上传失败、处理失败的独立记录和重试；
- 基于内容哈希的底层文件去重；
- 不同批次可分别关联同一个底层文件；
- 批次和文件处理状态查询；
- 当前已有资料迁移到“历史导入”批次。

本阶段不实现：

- 用户、角色和文档权限；
- 单个文件的分片续传；
- 文档版本、回收站和软删除（第二阶段）；
- 用户评分和反馈重排（第三阶段）；
- 问答范围和会话增强（第四阶段）。

## 3. 核心领域模型

### 3.1 导入批次 `upload_batches`

批次保存名称、资料分类、标签、备注、状态、文件统计以及创建和完成时间。状态包括：

- `DRAFT`
- `UPLOADING`
- `PROCESSING`
- `PARTIAL_FAILED`
- `COMPLETED`
- `CANCELLED`

批次的统计数字由文件真实状态计算或在同一事务中维护，不能只依赖前端累计。

### 3.2 批次文件 `batch_files`

批次文件保存批次、相对路径、原文件名、大小、内容哈希、上传状态、处理状态、重试次数、错误阶段、错误信息以及最终文档关联。

上传状态：

- `PENDING`
- `UPLOADING`
- `UPLOADED`
- `DUPLICATE`
- `FAILED`

处理状态：

- `WAITING`
- `PROCESSING`
- `PARSED`
- `INDEXED`
- `FAILED`
- `IGNORED`

同一批次内不允许存在两个活动的相同相对路径记录。单文件失败不得阻塞同批次其他文件。

### 3.3 底层文件 `stored_files`

底层文件保存唯一内容哈希、磁盘路径、大小、引用关系和创建时间。内容完全相同的文件只保存一次，并复用解析、切片和向量结果；业务文档和批次关联仍分别存在。

文件名相同但内容不同不视为重复。文件名不同但内容哈希一致视为底层重复。

## 4. 上传流程

1. 用户填写批次名称，可选填写分类、标签和备注。
2. 用户选择多个文件、整个文件夹或 ZIP。
3. 浏览器生成待上传清单；文件夹导入保留相对路径。
4. 服务端执行格式、数量、单文件大小、总容量和可用磁盘空间预检。
5. 前端默认以 3～5 个文件并发上传，服务端逐个接收。
6. 每个文件写入独立临时文件并计算内容哈希。
7. 已存在相同哈希时复用底层文件；否则原子移动到正式存储路径。
8. 每完成一个文件立即提交数据库状态，不等待整个批次完成。
9. 后台 worker 对待处理文件执行解析、OCR、切片和向量化。
10. 只有处理状态达到 `INDEXED` 的文档才标记为可检索。

## 5. 中断、继续与幂等

应用重新打开或网络恢复后不自动读取本地文件。用户进入未完成批次并点击“继续上传”，重新选择原文件夹或文件集合。

系统通过相对路径、大小和内容哈希匹配批次清单：

- 已成功且哈希一致的文件跳过；
- 内容已存在但本批次尚未关联的文件创建关联，不重复存储和解析；
- 未上传、失败或内容变化的文件重新上传；
- 重复请求不得生成重复文档、重复批次文件或重复处理任务。

本阶段采用文件级续传。单文件失败后重新上传完整文件，不实现文件内部的分片续传。

## 6. 失败与恢复

上传失败和后台处理失败必须区分。错误记录至少包含失败阶段、用户可读原因、内部错误码、重试次数和最后重试时间。

页面支持：

- 重试单个失败文件；
- 重试全部失败文件；
- 将不需要继续处理的文件标记为忽略；
- 取消批次；
- 按状态筛选批次文件。

服务启动时继续恢复遗留的处理中任务。临时文件不完整时可安全清理，不得影响已经进入正式存储的文件。

批次只有在全部文件进入 `INDEXED`、`DUPLICATE` 或 `IGNORED` 等终态后才为 `COMPLETED`；存在未忽略失败时为 `PARTIAL_FAILED`。

## 7. ZIP 与文件安全

- 文件名和相对路径必须规范化，禁止绝对路径和目录穿越；
- ZIP 解压前后限制文件数量、目录深度和展开后总大小；
- 拒绝符号链接和指向资料目录外的路径；
- 临时目录与正式资料目录分离；
- 校验成功后才以原子移动进入正式目录；
- 配置批次最大文件数、总容量、单文件大小和上传并发上限；
- 上传前执行磁盘空间预检查，并为解析、OCR和模型文件预留安全余量。

## 8. 页面设计

资料库保留原单文件入口，并增加“批量导入”和“导入批次”入口。

批次列表展示：名称、状态、总数、可检索数、处理中数、重复数、失败数、创建时间。

批次详情展示总体进度及文件表格，主要操作包括：

- 继续上传；
- 重试失败；
- 查看文件；
- 取消批次；
- 按上传或处理状态筛选；
- 查看相对路径、错误阶段和错误原因；
- 完成后跳转资料检索并自动限定当前批次。

页面轮询批次摘要和文件状态；轮询只更新数据，不造成整页闪烁。

## 9. 与现有系统兼容

- 已有文档通过迁移关联到系统生成的“历史导入”批次；
- 原文件路径、下载、解析状态、切片和向量保持有效；
- 原有上传 API 和页面继续可用；
- 原有混合检索、RAG、DeepSeek和 Harness 行为保持不变；
- 新增字段和表使用 Alembic 前向迁移，不清空数据库和存储目录。

## 10. 后续阶段预留

模型预留文档版本、停用检索、软删除、行为统计和评分的关联位置，但本阶段不启用这些行为。底层文件的引用关系必须支持未来在批次、文档和版本均无引用时再进行彻底清理。

## 11. 验收标准

- 一次选择并登记至少 200 个文件；
- 文件夹相对路径完整保留；
- 上传中途关闭页面后可手动继续；
- 已成功文件不重复上传或重复解析；
- 单文件失败不阻塞其他文件；
- 上传和处理进度分开展示；
- 支持单个和批量失败重试；
- 内容重复文件只保存和解析一次，但可关联多个批次；
- ZIP 导入不能写出指定存储目录；
- 当前已有资料继续正常下载、检索和问答；
- 原有单文件上传入口继续正常工作。

## 12. 验证策略

服务器侧遵循当前协作约定，以代码生成和静态检查为主；实际依赖安装、数据库迁移、前后端运行和浏览器验证由用户在 Mac 环境完成。

Mac 验证至少覆盖：正常 200 文件导入、重复文件、中途断开后继续、单文件上传失败、解析失败重试、程序重启恢复、ZIP非法路径以及现有功能回归。
