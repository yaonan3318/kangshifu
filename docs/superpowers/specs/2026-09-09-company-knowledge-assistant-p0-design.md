# 公司知识助手 P0 设计规格

## 目标

把现有本地 RAG 演示系统升级为可持续维护、检索质量可观察的公司知识助手基础版本。P0 聚焦资料可靠进入、文档治理、切片治理、检索精排与离线评测，不包含用户权限和企业渠道集成。

## 现状

系统已经具备多格式上传、解析/OCR、切片、BGE-M3 向量、本地 PostgreSQL 全文检索、pgvector 语义检索、RRF 融合、千问问答、可选 DeepSeek、引用和 Harness。批量上传已经支持批次、相对路径、中断后人工继续、失败重试和处理进度。

## 架构

保留 FastAPI、Vue、PostgreSQL/pgvector、磁盘附件和异步 Worker。新增知识库、标签、版本、软删除、片段治理和检索评测数据结构。资料检索、知识问答和 Harness 继续复用统一 `SearchService`，确保停用或删除内容不会从其他入口泄漏。

检索链路为：查询规范化与词典扩展 → PostgreSQL 全文召回 + BGE-M3 向量召回 → RRF 融合 → 可选 bge-reranker-v2-m3 精排 → 阈值与去重 → 结果或无可靠答案。

## 数据模型

### 知识库

`knowledge_bases` 保存名称、描述、启用状态和时间。每份文档必须属于一个知识库；迁移创建“默认知识库”并接收全部历史文档。

### 文档治理

`documents` 增加知识库、相对路径、版本号、前一版本、启用状态、软删除时间/原因和 JSONB 元数据。默认只有未删除、启用、知识库启用且属于最新有效版本的文档参与检索。

标签采用 `tags` 与 `document_tags` 多对多结构。文档删除先进入永久保留的回收站；恢复不重新 OCR。永久删除才清理附件、片段、向量和处理记录。

### 片段治理

`document_chunks` 增加启用状态、是否人工编辑、原始内容、token 数和更新时间。人工修改采用原子操作：新全文索引和向量成功后一起提交，失败则保留原片段。整篇重新解析会覆盖人工修改，执行前必须提示。

### 检索评测

`retrieval_test_cases` 保存问题、预期文档、预期关键词和是否应当无答案；`retrieval_test_runs` 保存参数快照、逐阶段结果、Recall@K、MRR、无答案判断、耗时与执行时间。

## 文档状态规则

- 停用知识库、文档或片段后，资料检索、问答和 Harness 均不可召回。
- 软删除保留附件、片段和向量，但所有普通查询排除。
- 永久删除需要二次确认；文件删除失败时保留数据库记录并允许重试。
- 新版本处理失败时继续使用上一成功版本；新版本完全可用后才成为默认命中版本。
- 批量导入允许部分成功，失败文件可单独重试。

## 页面

- 资料库：知识库选择器、知识库管理入口、标签/状态过滤和文档治理列。
- 回收站：查看、恢复和永久删除。
- 文档详情：基本信息、片段、处理记录、版本历史；片段支持编辑、停用、恢复和单片重建。
- 资料检索：知识库、标签、类型和日期过滤，匹配类型、阶段分数及当前检索模式提示。
- 检索实验室：展示规范化问题、扩展词、关键词候选、向量候选、RRF、精排分数、最终上下文、耗时和无答案原因；支持标准问题集和批量运行。

## Reranker 与降级

精排模型默认采用 `BAAI/bge-reranker-v2-m3`，按配置启用并懒加载，只处理前 20～30 个候选。模型未安装、加载失败、推理失败或内存不足时，本次查询自动降级为 RRF，不影响服务和其他功能。页面明确显示实际使用的检索模式。

普通检索不依赖 LLM，使用确定性的清洗、词典和同义词扩展。知识问答可选用本地千问提取检索词；千问不可用时继续使用规则查询。

## 无答案策略

最高精排/融合可信度和有效候选数量共同决定是否有可靠答案。低于阈值时，检索返回空结果及原因；知识问答明确说明公司资料中未找到可靠答案，不把无关片段交给模型。

## 评测指标

第一版支持 Recall@K、MRR、无答案判断准确率和平均检索耗时。运行记录保存完整参数快照，能够比较调整前后结果。P0 只预留用户反馈数据对排名的接口，不让少量反馈直接改变排序。

## 迁移与兼容

Alembic 迁移不得清空现有数据库。历史文档进入默认知识库，默认启用、版本为 1；历史片段默认启用。保留附件路径、哈希、OCR、向量和任务。迁移失败时后端启动失败并提示先升级数据库。

## 错误处理

- 精排不可用自动降级并返回告警字段。
- 片段修改或重建失败不提交半成品。
- 重新解析失败保留上一可用版本。
- 永久删除失败保留记录和错误信息。
- 所有后台失败记录可读错误码和错误说明。

## P0 边界

本期完成多知识库基础、标签/元数据、软删除/回收站、启停、版本关系、片段治理、查询规范化、词典、混合检索改进、可选精排、无答案判断、检索实验室、基础评测，以及三个检索入口统一过滤。

本期不包含用户/部门/权限、SSO、用户评分影响排序、企业渠道、外部资料同步、工作流、多智能体、GraphRAG 和回收站自动清理。

## 验证与交付

服务器侧执行静态检查和不依赖完整模型的轻量验证。提供 Alembic 迁移、模型准备、启动和 Mac 验证说明。新增模型能力均可配置关闭，关闭后保持现有功能可用。代码按可回滚的阶段提交后统一推送。
